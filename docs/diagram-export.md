# 図の出力

業務フロー、入力中の候補、会社・活動・システムの鳥瞰図で「この図を出力」を開けます。保存前の候補も、手順を訂正した後の構造も出力できます。出力だけでは、プロジェクトや原文を更新しません。

| 操作・形式 | 使い方 |
| --- | --- |
| 画像をコピー | PowerPointなどへ画像として貼り付ける。ブラウザーが画像のコピーに対応している場合に使える。 |
| PNG | 画像を保存して、スライドや文書へ挿入する。日本語フォントを使い、表示の2倍の解像度で描く。 |
| drawio.png | PNG画像として使う。draw.ioで開くと、図形と矢印を編集できる。 |
| SVG | 拡大して使う。Microsoft 365のPowerPointなど、SVGを挿入できるアプリで使う。 |
| drawio | draw.io用の編集できる図。 |
| JSON | 要素・関係・原文の根拠と、図の配置を別々に記録した構造データ。 |

PNGに図のデータを含める方法は[draw.ioの公式仕様](https://www.drawio.com/docs/manual/export/export-to-png/)に合わせています。SVGの挿入方法は[Microsoftの案内](https://support.microsoft.com/en-us/office/graphics-visuals/edit-svg-images-in-microsoft-365)を参照できます。

## 表示範囲を保つ

会社の鳥瞰図では、表示中の活動と関係を出力します。システムの鳥瞰図では、選んだ「情報の受渡し」または「稼働の依存」を出力します。対象の業務数、表示した要素・関係の数、現在・将来案・別案を図に記載します。ページを切り替えると、そのページの関係に変わります。

業務フローは最大6手順ずつ出力します。別のページに続く関係は、図の下の説明と構造データに残します。図の外の手順は構造データで`offPage`として区別します。保存前の候補には「保存前の候補」と記載します。

条件の全文と、戻り道・停止・保留を残します。長いラベルは図の上で省略し、説明と構造データに全文を保持します。推定・未確認は点線で示します。担当が不明な作業に、担当者やシステムを補いません。

## 業務の意味と配置を分ける

[「bpmn.ioで始めるAI-Readyな業務フロー管理」](https://future-architect.github.io/articles/20261009a/)の、業務の意味と図の配置を分ける考え方、粒度を明示する考え方、構造の検査と業務内容の確認を分ける考え方を取り入れています。

出力データの`schema`は`businessflowlens.diagram`、`version`は`1`です。

- `semantic`は元の手順キー、鳥瞰の要素・関係ID、担当、実行方法、システム、情報、処理結果、条件、原文の根拠、元資料の参照、人の訂正を持ちます。業務フローには未回答の質問と除外した候補も残します。鳥瞰の関係には、集約の根拠になった業務・手順・情報の参照を残します。
- `view`は表示中の要素と線の座標、色、短いラベルを持ちます。図の配置を変えても、業務の意味や元のIDは変わりません。
- `scope`は図の粒度と表示範囲、候補か保存済みかを持ちます。
- `checks`は未登録の接続先、条件が書かれていない分岐・繰り返しなどを示します。業務内容が正しいか、条件分岐か並行処理かは、原文と人の確認が必要です。

draw.ioの図では、図形・矢印の`bflId`と`bflType`に元のIDと種類を残します。タイトルの`object`の`bflModel`に構造データを記録します。draw.ioが再保存時に削除する図全体の属性には置きません。drawio.pngは最初の`IDAT`より前に、`mxfile`をキーとする`tEXt`を入れます。値はURIエンコードしたXMLです。

業務フローの接続には、候補全体での順番から出力用のキーを付けます。同じ候補をページごとに出力しても同じキーになります。保存したグラフの永続的なエッジIDとは区別してください。

接続先のない作業に開始・終了イベントを足したり、分岐を排他ゲートウェイと断定したりしません。BPMNの実行用ファイルへの変換は行っていません。

## 制約

draw.ioで編集した図を、BusinessFlowLensへ取り込んで構造を更新する機能はありません。図に含めた構造データは、出力時点の記録です。draw.io上で名前や配置を変えても、この記録は自動で書き換わりません。

元のPDFやOfficeファイル、画像のバイト列は図に埋め込みません。元資料への参照ID、ファイル名、ハッシュは構造データに残します。元ファイルも渡す場合は、元資料から別途保存できます。

SVGの日本語は、挿入先のフォントにも依存します。PNGは日本語を画像に描くので、挿入先のフォントに左右されません。Microsoft PowerPoint本体での貼り付けは今回の環境では未確認です。

大きな構造を一枚に詰め込まず、表示した範囲を出力します。リクエストは2MiB、PNGファイルは8MiBまでです。画像の面積と要素数も制限し、大きすぎる場合は出力画面で理由を表示します。

## 2026年10月12日の確認

既存プロジェクトを変更せず、独立したSQLiteデータと検証用のメモを使いました。

| 入力・操作 | 確認したこと |
| --- | --- |
| 0業務のプロジェクトで「Outlookで注文を受け取る→Excelで確認→SAPへ入力」と入力 | 保存前に図とJSONを出力できる。「保存前の候補」と表示される。 |
| 担当・作業・結果・業務名を訂正し、業務の行為ではない候補を除外 | 出力の名前・要素・手順数が変わる。訂正前の根拠と人の訂正、除外した候補はJSONに残る。保存後も同じ構造を読める。 |
| 品質判定の独立データで、規格外の再調整→再判定、合格時の承認→MES、2回でも規格外なら保留 | 分岐、戻り道、保留、未確認の担当を図と編集用データに保持する。 |
| UIから保存したdrawio.pngをdraw.ioへ読み込み、判定の図形を動かしてXMLを再保存 | 一枚の画像ではなく、図形と矢印として読み込む。移動後も矢印が接続先に追従する。再保存後も出力時点の構造・根拠・訂正が残る。 |
| 架空の化学メーカー303業務を開き、会社・システムの鳥瞰を出力 | 現在の300業務を対象に、最大8要素・6関係ずつ表示・出力できる。関係ページ、受渡し・依存、現在・将来案の切替を確認する。 |
| 自動テストとApp Runtimeの配布物からのHTTP出力 | PNG・drawio.png・SVG・drawio・JSON、XMLのエスケープ、日本語フォント、表示範囲、保存データを更新しないことを確認する。 |

この変更ではAI抽出の精度を再評価していません。初回入力の検証はAI未接続の簡易整理です。「その後の担当は、まだ分からない」という文が手順候補になる制約も確認しました。候補を除外し、原文を残したまま出力できることを確認しています。303業務は合成データによる表示・出力の検証で、AIによる300件の入力検証を意味しません。
