# Excel・PDFから仕事を読む

ヒアリングで書き直さず、手元の資料から始められる入口を「話を入力」に追加した。「Excel・PDFから始める」で資料を選ぶと、AIが資料内の仕事を分けて候補を出す。仕事を選ぶと、保存前のフローと担当・道具・情報が開く。その場で訂正して保存できる。同じ資料の次の仕事へ戻り、未読・保存前・保存済みを確認できる。

原資料のファイルと、読み取ったセル・ページはプロジェクトごとに保存する。フローの原文、AIの整理、人の訂正とは分けて保持する。手順の「元資料のセル・ページを確認する」で原資料へ戻り、空欄や注記も読める。同じファイルの再取り込みでは元資料を重複登録せず、保存した業務分けを使う。元のファイルも保存できる。

取り込んだ資料は最近20件から選び直せる。ExcelからPDFへ、PDFからExcelへ切り替えるための再アップロードは不要。保存した仕事を再読み込みした場合も、対応する資料と保存済みの状態を開く。

## 検証資料

化学メーカーの内部監査を想定した架空のExcelとPDFを作った。Excelは結合セルと12列の表に四業務・17作業を詰め、別シートに工場差分と監査指摘を記載した。担当の空欄、解除条件の未確認、未承認の将来案も含めた。PDFは設備の開始・停止・交替引継ぎを三ページにまとめ、紙の理由、条件による保留、受取記録と保留解除の違いを記載した。資料内の業務IDや作業番号だけで、別の業務を接続しない。

監査資料の表形式を検討する際、[農林水産省のFCP工場監査シート](https://www.maff.go.jp/j/shokusan/fcp/mieruka_step/attach/pdf/library_koujou-3.pdf)を参考にした。添付例の業務内容は独自に作成した架空の内容であり、食品監査の内容を化学メーカーへ転用していない。

## 実際の操作

独立した検証プロジェクトに、ブラウザーのファイル選択でExcelをアップロードした。Codex App Server経由の実gpt-6-lunaで業務を分け、東西の材料収支、逸脱報告、再調整、東西の版配信という六候補を確認した。AIが作った概要を、原資料の事実として再入力しない。

東工場の材料収支では、電子秤の重量をExcelへ人が転記する現行運用を四手順で保存した。未承認のMES自動連携を現行の作業にせず、差の許容基準、照合担当、確認依頼後の再開先は未確認を保った。保存・再読み込み後も、元資料の参照と原文を確認した。

逸脱報告では、DCSの記録、QMSへの登録、MESのロット、LIMS追加検査・Teams保留連絡と、問題なしの場合のQMS判定を四手順で読んだ。保留解除時期と次の仕事は未確認だった。再調整では、Excelの数量案、品質課長の承認、MES・Teamsの指示、許可方法がない場合の研究への相談を確認した。空欄の相談担当にAIが前の担当を補ったため、図から未確認へ訂正した。抽出の品質と、訂正できる操作の成立は分けて評価する。

最初の実操作で、業務候補のボタンが720px高の画面の下に隠れた。ボタンを各候補の見出し直下へ移すと、最初の二候補のボタンが588〜629pxに入り、スクリーンショットでも見えた。原資料の確認ボタンも、長いメモ一覧の下から選択手順の上へ移し、199〜240pxで見えた。

原資料の最初の表示は、横に長い表と結合見出しの繰り返しで読みづらかった。セルを三列の項目表示にし、同じ結合元の文字を一度だけ表示する。選択手順の根拠の文字と一致する行を先に表示し、全箇所へも切り替えられる。材料収支の二手順目ではA6:L6の12項目と戻るボタンを、横スクロールなしで確認できた。一致がない場合は、関連する原資料全体を表示する。

PDFの業務分けでは三候補が出たが、資料にない「製造ライン（B155）」等を対象工場として補っていた。対象名がその仕事の元資料に実際に書かれていることを検証し、確認できない対象は工場の区分に使わない。候補の概要に確認できなかったことを示す。修正後、同じPDFを選ぶと、元資料のIDと三候補は保ち、根拠のない工場名を除いた。

開始前の確認は四手順で保存した。問題なしの開始許可と、残留物時の開始保留・清掃依頼が分かれ、依頼する人と再開先は未確認を保った。紙を使う理由は原文から人が補った。原資料のPDF一ページを表示し、画面から保存したPDFがアップロード時のファイルと同じバイト列であることを確認した。

停止業務は五手順で読んだ。班長の製造終了・液位確認から、DCSへの停止指示と、基準外の無線相談が分かれた。DCSの結果送信と人の設備点検を分け、停止基準の数値、相談後の戻り先、結果の連携方式は未確認を保った。「確認する」という結果の候補は、人が製造終了と液位の条件を明示する説明へ訂正した。

最終表示で、資料の選び直しを含めてもExcelの最初の流れを開くボタンは592〜633pxにあり、720px高の画面で見えた。単体テスト282件、隔離したSQLiteでのAPI回帰42件、型検査と本番ビルドが成功した。これらは文字・参照・保存・表示の回帰検証であり、実AIの抽出精度とは分けている。既存10プロジェクトの構造・原文・改訂は保持した。

## 工場差分と、受取記録を解除と扱わない確認

PDFの引継ぎも保存した。MES・QMSの状態をSharePointに一版で保存し、Teamsで次の班へ渡し、受取をMESに記録する。保留中の製造は、受取を登録しても始めない。AIがこの引継ぎ自体の停止とした指定を人が外し、元の方針を結果の説明に残した。実AIで確認事項を見直した後も人の訂正、原資料、保留解除とは異なる受取を保った。操作691〜695に記録した。

西工場の材料収支の初回候補では、自動送信がExcelへの転記と一手順になり、倉庫・環境担当が道具に入った。図から道具をTeamsへ訂正し、本文へ原資料の自動送信と人の転記を分ける補足を入れた。実AIの再整理で五手順となり、設備データ基盤への自動送信、Excelへの転記、差の判断、MES確定、Teamsの確認依頼を読めた。送信元の装置、基盤からMESへの方式、差の基準、依頼後の再開は推測で補っていない。将来のMES自動連携も現行へ入れていない。操作699・703・704に記録した。

西工場の版配信では、原資料の東工場限定のAPI行を入力範囲へ入れず、現行CSVの手渡しを六手順で確認した。未確認のCSV取込担当、返却方式、版照合の担当、旧版への戻し方・承認者を保った。承認された条件は、承認する手順で受け取る情報から新しく作る情報へ人が訂正した。API導入の将来案は現行の自動処理にしない。操作706〜708に記録した。

Excelの六候補、PDFの三候補を、原文と未確認事項を保持して保存した。これらは、手入力で150件を積み上げた同じ独立検証プロジェクトへの追加であり、既存プロジェクトは変更していない。

## 読み取れる範囲

対応は.xlsxと文字を選択できるPDF、8MBまで。Excelのセル・注記・結合元と保存済みの数式表示値、PDFの文字とページ位置を読む。マクロ・外部リンク・数式は実行しない。スキャン画像のOCR、図形・矢印・写真・埋め込みファイルの内容は未対応で、画面に明示する。PDFの表の列対応は元ページで確認する必要がある。

大量の資料は対象を分ける。上限は40シート、80ページ、700行・ページ分の読み取り単位、9万文字。上限を超えた資料は一部だけ取り込まず、分割を案内する。AIによる業務分けは40候補まで。AI未接続時も原資料は保ち、業務分けには接続が必要だと案内する。

AIが毎回同じ業務の分け方、引用、担当、分岐を出す保証はない。元資料、推定・未確認、利用者の訂正を残して確認する。
