# 対話から図の接続・訂正・統合を進める

「続きを話す・図を直す」へ、業務の説明と、図へのお願いの両方を入力できる。説明は原文や回答として保持し、接続・統合・保存などの操作は別の履歴に残す。AIが読み取った操作対象を、実在する業務・手順・System・DataのIDと照合してから案を作る。

追加・訂正の案は、読み取り後の図と差分で確認する。元の流れを表示したまま承認を求めない。まだ反映していない案と、反映済みの変更を区別し、「それで反映して」「やっぱり取り消して」などの返答を使える。案を開き直す場合は保存した読み取り候補を使い、同じ案を再抽出して変えない。

業務内の矢印、条件分岐・戻り先、業務間の受渡し、途中の作業、説明の訂正、手順の除外と復元、業務名・表示する状態、業務統合、System/Dataの名寄せと名称変更、保存、直前の変更や保存した統合の復元、表示切替を扱う。元の詳細編集も使える。

統合では採用する担当・道具・結果などを確認する。現行と将来、別の工場・製品・期間を、似た名前だけで同じ業務として扱わない。System/Dataの名寄せは元の名前を別名として残し、元のプロフィール・関係・根拠を復元用に保存する。同一性を確認したことを理由に、未確認の利用関係を確定しない。

変更案の表示はプロジェクトを書き換えない。保存済みの統合と復元は更新時刻を照合して保存し、後から追加された関連情報を上書きする復元を止める。無関係な後続の入力は残す。取り除いた業務間接続は再読取でも除外を保持し、人が明示的につなぎ直した場合に復元する。

## 続けて確認すること

会話で対象を取り違えると、適用を止めて確認が必要になる。抽出と操作対象の解釈を、根拠の確認やID照合で検証する必要がある。単体テストの通過だけで実AIの精度を保証しない。

名寄せ後の以前の要約・質問と、現在の構造の説明を揃える作業はIssue169で続ける。現行を保持した将来案の複製、システムのプロフィール・依存関係、比較と報告、会社の鳥瞰からの対話操作はIssue170で続ける。300業務を実際の入力から蓄積して全機能を操作する検証はIssue27で継続し、この変更だけでゴール完了とはしない。
