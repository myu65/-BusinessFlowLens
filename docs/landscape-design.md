# 分類・範囲・物の流れを扱う鳥瞰

Issue: https://github.com/myu65/-BusinessFlowLens/issues/7

## 見る軸

| 軸 | 例 | 意味 |
| --- | --- | --- |
| 分類（複数可） | サプライチェーン、エンジニアリングチェーン、会計、研究開発、品質、任意分類 | 業務が担う機能・チェーン。分類が同じだけでは業務順序は決めない |
| 工場・拠点 | A工場、B工場、開発拠点、全社共通 | 業務の実施場所・適用先。未登録を全社共通とは解釈しない |
| 製品ID／名称 | P100／ポンプA | 同じIDを登録した業務を関連づける。名称だけでは同一視しない |
| 視点 | 設計、製造、原価、品質 | 同じ製品をどの業務的な側面から見るか |
| 共通業務ID・位置づけ | INSPECT、共通の業務定義／拠点での実施 | 共通の概念と工場別実施を対応づける。各業務の手順は独立 |
| 実施方法・差分・根拠 | A工場はバーコード、B工場は紙 | 類似業務の違いを明示。システムや手順の一致から共通業務を推定しない |

視点や分類を技術的なスキーマ／テーブル名に置き換えない。製品IDは利用者が定める業務上の同一性のキーであり、現段階では外部製品台帳との照合を行わない。

## 範囲と関心

- 現状・将来案・代替案の対象を先に選び、分類／工場／製品／視点／検索を同時適用する。
- 注目業務だけ、注目業務と直接の関係先、関心業務と直接の関係先を選べる。
- 直接の関係は同一製品ID、共通業務ID、共有データ、明示された物の受け渡し。一段に限定し、近傍の近傍まで自動展開しない。
- 関係先が条件の外にあるときは境界の関係を案内し、条件を広げて見る操作を用意する。フィルタ外の関係先を画面から消して関係がないように見せない。
- 関心業務と範囲・切り口はブラウザのlocalStorageに保存する。同じブラウザで再利用できる。端末間の共有は対象外。
- 鳥瞰の切り口は分類と関係、製品の視点、共通業務と工場差分、物とデータ、データ利用、目的と手順。同時に全詳細を並べない。

## 物とデータ

物の移動はシステム間データフローから独立し、送り元業務の `landscape.materialHandoffs` に保存する。送り先業務・物の名前・送り元／先の場所・製品ID・ロットや追跡キー・対応する業務データ・根拠を記録する。

| 対応状態 | 表示と入力条件 |
| --- | --- |
| 未確認 | 物の記録だけで登録可能。未記録を途切れと断定しない |
| 対応を確認済み | 対応データと確認根拠が必要 |
| 途切れを確認 | 途切れの根拠が必要。物の流れは維持し、データ対応の問題として表示 |

同じ業務内の移動は異なる送り元／先の場所が必要。送り先が表示範囲やシナリオ対象の外でも、物の記録の片側が範囲外と表示する。入力された移動の方向を表示し、同一製品／共通業務の関連線とは区別する。

現段階では手動記録の対応を表示する。センサー・在庫・ロット台帳を実接続して照合したり、実際の追跡欠落を自動検知したりはしない。

## 保存と複製

SQLiteのworkflowsに任意の `landscape_json` を追加し、既存データを維持する。既存業務の再抽出では位置づけと物の流れを保持する。物の流れだけで参照されるデータも削除しない。共有データ統合・ID正規化は物の流れのデータ参照にも適用する。

「別の拠点での実施を作る」は保存済み手順と詳細を複製し、共通業務IDで元業務と関連づける。新しい拠点は独立した業務・シナリオ系列を持つ。拠点の実施方法は要確認と明記する。物の流れは複製先で確認して登録する。元業務の入力メモは複製先のヒアリング記録として自動転記しない。

将来シナリオの分岐でも分類・製品・視点を引き継ぐが、現状の物の移動を将来案へ自動コピーしない。分類編集はプロジェクト自動保存の対象であり、業務手順Revisionとは独立する。
