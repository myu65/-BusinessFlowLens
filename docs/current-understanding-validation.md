# 図の更新と、現在の説明・確認事項

名寄せ、追記、担当や接続の訂正の後は、図に登録された作業・道具・情報を説明する。作業の並びだけから、前後関係や完了を文章で確定しない。以前のAIの要約は「以前の読み取り・説明」に残し、人の訂正の根拠と一緒に読める。

対話で、指定した質問だけを確認済みにしたり、もう一度確認する質問に戻したりできる。確認した理由と元の質問を保持する。「同じシステムだと確認した」ことを理由に、管理部署や次の作業などまで解決しない。再読取では確認履歴もAIへ伝え、保存・再表示にも保持する。機械的な除去は同一の質問に限り、言い換えや範囲の違う質問の解釈は実AIで検証する。

人が確認したSystem/Dataの正式な名前と別名を再読取にも使う。原文の言葉や引用は書き換えず、道具・情報の参照先だけを同じ資産へ揃える。AIが提案した別名だけでは適用しない。

取り消した名寄せを戻す際は、名寄せで変えた項目を照合して復元する。後から答えた独立した質問や対話は保持する。関係する構造や説明を後から編集していた場合は、その内容を上書きする復元を止める。

どちらの入力方法でも、操作を特定するための質問と返答欄を表示する。質問自体を図の変更案として承認できない。取り消した質問は、履歴を保存して開き直しても再開しない。

## 実AIと操作で確認したこと

2026年10月5日、独立した`dialogue-merge-20261005`でgpt-6-lunaを使った。LIMSと同じか不明な検査結果台帳を同じ仕組みだと明示して名寄せした。図と現在の説明はLIMSになり、原文には台帳という呼び名が残った。名寄せ前の要約も展開して読めた。

「同一性の確認事項だけ確認済みにして。管理部署と後続作業はまだ未確認」と依頼し、対象の質問だけを解決した。保存・再表示後も残った2質問、確認した理由、元の質問を読めた。

その後、「ここまでの話で確認事項を見直す」を実行した。初回の再整理では、確認履歴を戻す処理がAPIの戻り値で抜けており、同一性の質問が言い換えられて再表示された。この問題を修正し、人が確認した呼び名も再適用した。修正後の実AIでは管理部署と後続作業の2質問が残り、同一性の質問は再発しなかった。図と説明の道具はLIMS、根拠の原文は台帳のまま保持した。保存・再表示後も同じ内容だった。読み取り時点の未確認の警告は、現在の登録内容や人の確認とは分けて表示する。

「まとめて書く」から、相手を指定しない統合のお願いを入力した。AIは業務を指定する質問を返し、図は変えず、同じ画面で質問と返答欄を表示した。この質問を取り消して保存すると再表示される不具合も発見し、修正した。

操作記録は`.data/qa-ai-growth/831-*`、`832-*`、`834-*`から`838-*`に残した。既存10プロジェクトは、構造・原文・版履歴の保存前の記録と一致した。

360件の単体テスト、68件のAPI回帰、型検査を含むproduction buildで、独立した後続回答を残す名寄せの復元、AIの別名を自動確定しないこと、質問の解決・再確認と再読取、SQLiteへの保存、現行・将来の範囲、既存の接続の未確認への訂正と以前の人の訂正の保持を確認した。API回帰の簡易抽出と実AIの品質は、別の検証として扱った。
