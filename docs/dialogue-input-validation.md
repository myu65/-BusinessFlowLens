# 図を見ながら対話で整理する

「対話で整理」と「まとめて書く」は同じ本文・候補・回答を編集する。対話では自由な話から始め、確認事項に一つずつ答えられる。「まだ分からない」は事実の回答として使わず、未確認事項と履歴に残す。図の変更と対話の更新件数を保存前に確認できる。

以前の回答を訂正すると、訂正前の本文と補足元を残し、新しい回答から古い回答を参照する。抽出には有効な回答だけを渡す。過去の回答は、保存した引用が存在するかの確認に使う。訂正した担当を元の回答から復活させたり、過去の受渡しを現在の事実として取り込んだりしない。

対話・まとめ入力の切替で本文、書きかけの回答、訂正対象を保持する。別の確認事項に書いた回答も読み直しに含める。資料から始めた場合は原図のプレビューを対話の横に残し、元ページを拡大し、原本をダウンロードできる。

## 実操作

2026年10月5日、既存の10プロジェクトを保ち、独立した`dialogue-input-20261005`を使った。gpt-6-lunaへ「届いた成績書を誰かが確認します。結果はどこかに登録して、必要なら担当者へ知らせます。詳しい順番や担当はまだ分かりません」と入力し、保存前の3手順と未確認の担当・道具・順番を確認した。業務名を先に作る操作は不要だった。

本文を入力途中で両モードへ切り替えても内容が残った。質問への回答も書きかけで切り替え、その後、購買担当・Outlook・LIMS・Teamsを図へ反映した。

まとめ入力で別の確認事項へ「連絡はLIMSへの結果登録の後に行います」と書き、対話へ切り替えて未確認の連絡条件へ答えた。両方の回答が履歴に残り、LIMSへの登録からTeamsで連絡する矢印を確認した。分からない連絡条件は引き続き質問として残った。

「確認・登録は品質担当、連絡は購買担当」と以前の回答を訂正し、まとめ入力へ切り替えて反映した。変更は二つの担当に限られ、連絡担当と道具を保持した。「訂正前の回答」「訂正した回答」を履歴で読めた。その後に本文を補足して再整理しても担当の訂正を保持し、未確認の連絡条件と順番を確認事項として残した。古い回答の引用を誤って引用不一致と表示する問題を直して再整理した。

`rework-flow-20261005`では、標準試料の作り直し後の担当に「まだ分からない」を選んだ。次の質問へ移り、保存・再表示後も元の5手順、未確認3件、後で答える質問、回答履歴を保持した。

PDFとPNGを統合した`pdf-arrows-20261005`では、元ページの画像2枚を実AIへ直接渡し、対話で品質課長の合否判断を追加した。元の受取担当の訂正、Teamsの受渡し、除外した直通の矢印、社外の内部が見えないことを保持した。合否判断の順番と判定後の進み方は接続せず、確認事項として残した。LIMSに合否を記録する処理は追加していない。

原図のプレビューから元資料を開き、PDFとPNGの画像・読み取りを確認した。「フローへ戻る」で同じ受取手順へ戻り、購買担当とTeamsへの受渡しを確認した。

339件の単体テスト、型検査、production build、58件のAPI回帰テストで、訂正の参照、過去と現在の根拠の区別、未確認の保持、他モードの回答、SQLiteと版履歴への保存を確認した。API回帰はAI未接続時の保存契約と簡易抽出を検証し、実AIの意味の解釈は上の実操作で別に確認した。

## 継続する検証

AIによる通常の再整理では、未修正の説明や接続の候補が変わることがある。原文と差分を見て確認する必要がある。資料間の相違や既存の人の訂正との不一致は、注意事項に残す。
