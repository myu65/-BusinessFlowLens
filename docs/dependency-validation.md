# npm依存の更新と検証

2026年10月5日、元のlockfileを隔離ディレクトリへコピーしてnpm ciを実行した。ExcelJSの内部依存からinflight、lodash.isequal、rimraf、glob、fstreamの非推奨警告が五件出た。npm auditではNext.jsが使うPostCSSに中一件・高一件が報告された。

ExcelJSのCSV、ZIP展開、ファイル検索の依存と、Next.jsのPostCSSを、対象を限定したoverridesで更新した。圧縮用のArchiverはExcelJSのStreamBufと互換性がある5.3.2を使う。Archiverの新しいメジャーでは書出しに失敗することを実際のストリームのテストで確認したため、まとめて最新版へ変更していない。

npm 11.17が出すインストールスクリプトの警告は、esbuild 0.28.2の処理を確認し、その版だけをallowScriptsへ記録した。システム全体のnpm設定は変更していない。esbuildの版が変わる場合はスクリプトを再確認する。

更新後のpackage.jsonとlockfileを新しいディレクトリへコピーし、空のnode_modulesから通常のnpm ciを実行した。非推奨警告、インストールスクリプトの未確認警告、脆弱性の報告はゼロだった。警告表示を抑える設定やnpm audit fix --forceは使っていない。

単体テスト293件、型検査、本番ビルド、独立した検証用データベースでのAPI回帰テスト42件を確認した。監査Excelの結合セル、空欄、コメント、数式の保存値、工場差分と、三ページのPDFを読み取るテストも成功した。追加の互換性テストでExcelのストリーム書出し、通常読込み、インライン文字のストリーム読込み、CSVの日本語・カンマ・改行、圧縮ライブラリのファイル検索を確認した。

ExcelJSのストリーム読込みでは、共有文字列が値ではなくインデックスのまま返る場合がある。更新前・更新後の両方で再現した。アプリは通常のWorkbook読込みを使い、共有文字列のセル値も既存の資料読取りテストで確認している。

CIにもnpm auditを加えた。今後ライブラリの上流で依存が更新されたら、資料読込みと互換性の回帰テストを通してoverridesを見直す。
