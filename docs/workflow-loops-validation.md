# 業務フローのやり直しと繰り返し

業務内の接続には、前の手順への戻りと、同じ手順への繰り返しを記録できる。接続には条件、原文の根拠、確認状態、人が訂正した履歴を保持する。繰り返しを表すために、同じ作業を何度も登録する必要はない。

同じ手順への矢印が手順の箱に重なって見えなかったため、箱の外を通るように修正した。戻りによって検査や通常経路の配置が変わる問題も修正した。入力の候補と保存した業務フローで、青い戻り矢印と「やり直し・繰り返し」を表示する。条件の全文は図の下と選んだ手順から読める。表示は6手順、戻りの説明は3接続ずつに区切る。

戻り先の選択には「同じ手順を繰り返す」「戻り先」を明示した。保留を伴わない再検査と、停止・保留中の対応を区別する。繰り返す回数と待ち時間は接続の条件に書ける。分岐の案内ボタンから選択肢へ移動でき、同じ手順への繰り返しは「前の手順」として扱わない。

## 実AIでの入力

2026年10月6日、独立した`loop-review-20261006`でgpt-6-lunaを使い、2つの説明を入力して保存した。

樹脂の粘度検査では、「規格外なら配合を再調整して同じ検査へ戻る」「規格内ならLIMSへ合格結果を登録して出荷準備へ引き渡す」「2回の再調整後も規格外なら出荷を保留する」と説明した。AIは6手順と戻りの接続を作り、説明にない保留解除の方法を確認事項として残した。戻る条件は空欄だったため、編集の検証では原文を確かめて「配合の再調整後」と補足した。

APIの再送では、「通信エラーなら30秒待って同じ送信へ戻る」「初回を含め最大3回」「成功したらMESが製造指示へ反映する」「3回とも失敗したらTeamsでIT担当へ通知して保留する」と説明した。AIは4手順に整理し、待機から送信への戻り、成功と上限到達の分岐を作った。再送条件の一部は推定のまま残し、保留を解除する方法を補完しなかった。

## 編集と保存後の実操作

AIの結果を独立したSQLiteへ複製した`loops-edit-20261006`で、入力と図の編集を検証した。この編集用サーバーはAI未接続で、抽出結果は実AIで作った候補を使っている。

樹脂の再調整から戻る条件を補足すると、追加・除外された接続の差分と原文の根拠を確認できた。保存後、入力画面から業務フローへ移り、再調整から検査へ戻って3つの分岐を読んだ。

再送では、30秒の待機を繰り返し条件にまとめるため、独立した待機の手順を候補から除外した。「通信エラーで送信が3回未満なら、30秒後に再送」を条件として同じ送信への矢印を追加した。元の説明、除外した手順、人が確認した根拠を残し、保存・再表示後も3手順と自己ループ、成功と保留の分岐を保持した。手順の除外によって生じた接続の確認事項は、人が明示的に確認済みにするまで残る。

300業務の化学メーカーサンプルにこの2つの実AI入力を加えた`loops-company-20261006`は、現行302業務と将来案3業務の計305業務を持つ。この中でも6手順だけを表示し、再調整から検査へ戻る2操作と状態取得が約0.9秒で応答した。これは操作時の確認値であり、一般的な性能保証ではない。既存の会社サンプルやAI入力の蓄積は変更していない。

## 検証範囲と制約

矢印が手順の箱を横切らないこと、戻りを追加しても検査と通常経路の配置を変えないこと、条件の全文、未確認の条件、密な接続のページ分け、SQLiteでの自己ループと根拠の保持、押せる分岐の案内をテストした。既存の循環と30手順・300手順の表示検証も継続する。

AIがすべての戻り先や条件を正しく読むとは限らない。今回も原文からの条件補足が必要だった。回数や待ち時間は知識グラフの条件として保持し、実行回数を数えたり処理を再実行したりする仕組みは追加していない。業務間の戻りは既存の受渡しとして記録し、この変更の図と接続編集は業務内を対象とする。
